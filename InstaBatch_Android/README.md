# InstaBatch Android and backend

This repository contains the Android client and a small Flask backend. The backend accepts Instagram post/reel URLs, runs `yt-dlp`, and exposes the finished files to the Android client. Use it only for content you own or have permission to download, and follow the source platform's terms.

## Deploy a limited Render beta

1. Push this repository to GitHub. In Render, choose **New > Blueprint** and select the repository. Render reads the root `render.yaml`; the service root is `InstaBatch_Android/backend/`.
2. Set `APP_PASSWORD` in the Render service's environment settings. `SECRET_KEY` is generated by the Blueprint. Treat both as secrets; do not put them in the APK source or commit them.
3. Wait for the service to deploy and copy its HTTPS URL.
4. Install the signed APK on a phone. Enter the Render HTTPS URL in **Backend HTTPS URL** and the `APP_PASSWORD` in **App password**.

The single shared app password is suitable only for a small, trusted beta. Anyone who knows it can use the service. This configuration has per-client job limits and basic rate limits, but it does not provide user accounts, billing, or strong anti-abuse controls. Do not advertise it as an unrestricted public service.

Render's free service can sleep and its local filesystem is ephemeral. This Blueprint stores its SQLite database and videos under `/tmp`, so a restart or redeploy can remove jobs and files. Free Render does not provide the persistent disk needed for durable downloads. Treat this as a test deployment, not reliable public hosting.

Instagram may deny downloads or change its pages. The backend cannot access cookies from a user's phone and does not attempt to bypass account restrictions. The service caps each batch at 10 URLs, limits each file to 250 MiB by default, uses a maximum of 3 worker threads, and removes completed files after 24 hours.

## Backend configuration

Required:

- `SECRET_KEY`: long, random Flask session-signing key.
- `APP_PASSWORD`: shared password required by the API.

Optional limits and storage paths:

- `MAX_WORKERS` (default `3`, maximum `3`)
- `MAX_ACTIVE_JOBS` (default `8`)
- `MAX_CLIENT_JOBS` (default `2`)
- `RATE_LIMIT` (download batches per client per hour, default `6`)
- `MAX_FILE_MB` (default `250`)
- `CLEANUP_HOURS` (default `24`)
- `DATA_DIR` and `DATABASE_PATH` (temporary defaults under `/tmp`)
- `RATELIMIT_STORAGE_URI` (defaults to process memory; use shared Redis for multi-instance deployments)

## Local backend development

From the repository root:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements-dev.txt
cd backend
export SECRET_KEY="$(python3 -c 'import secrets; print(secrets.token_hex(32))')"
export APP_PASSWORD='choose-a-private-test-password'
export COOKIE_SECURE=false
.venv/bin/python -m pytest
gunicorn --workers 1 --threads 4 --timeout 120 wsgi:app
```

The API listens on port 8000 by default when run with Gunicorn. For local phone testing, use a reachable HTTPS tunnel; do not expose the development server directly to the internet.

## API contract

- `POST /login` accepts form field `password` and header `X-Client-ID`, then returns an authenticated session cookie.
- `POST /api/download` accepts JSON `{ "urls": [...], "quality": "best" }` and returns a `job_id`.
- `GET /api/status/<job_id>` returns `status`, `total`, `done`, and log messages.
- `GET /api/files` returns files belonging to the signed-in client.
- `GET /api/files/<file_id>/download` serves that client's file.
- `GET /healthz` is the Render health check.

## Android builds

The Android project is in this repository root. Build a debug APK with `gradle assembleDebug`. For a signed release APK, use `bash build-release.sh`; the release signing key is stored outside this repository under `~/.local/share/instabatch-android/`.
